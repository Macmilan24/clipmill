# ClipMill 0.6.0

ClipMill's local editor now reads the whole recording before it cuts, and
checks each clip the way an editor would before it suggests it. Clips start
and end on whole thoughts, every cut sits in a pause, and a clip built from
several parts of the recording is suggested only when it is the better short.

## Clips that start and end on whole thoughts

- A clip ends where another speaker takes over, or where the same speaker
  finishes a sentence and pauses. It no longer stops while the speaker runs
  straight on, before "and…", "but…" or "however…", on a promise such as
  "here's why", or on a question someone else then answers.
- A clip opens at the same kind of place, never on a reply such as "I agree…"
  or "No, …" to a line the viewer did not hear, and neither opens nor finishes
  on a greeting or thanks.
- Before planning, **Check the endings** tests the editorial model on endings
  whose answer the recording gives. A model that tells them apart is then asked
  about each candidate ending where the speaker goes on, and an ending it hears
  as cut off is replaced by a later one.
- Every clip edge, join and removal is placed in a pause measured in the audio,
  so a cut no longer clips a syllable.

## Edits, only when they are better

The editor can lift a strong line to the front, join a question to an answer
given minutes later, open on the question an answer needs, or leave out an
aside. Each such edit is set against the same moment played whole, and a judge
is asked which makes the better short, both ways round. The edit is suggested
only when it wins both times. The judge is first tested on pairs whose answer
the recording shows, and when no judge passes, the moment is suggested whole.
Expect most clips to be single stretches of the recording. The Clip Inspector's
**Why** tab says how an edit fared.

## Results, the Clip Inspector and the Editor

Clips built from several parts appear in the Results grid and list like any
other clip. The Clip Inspector plays their parts in order, marks each part on
the timeline and in the transcript, and lists what the review found. Approving
one builds its edit; in the Editor's **Parts** tab you can move, remove or
restore a part. Keeping, approving and rejecting clips informs later analyses
of the same project.

## Connected agents

- Agents can search a recording's memory, read each clip's plan and evidence,
  try a new brief without transcribing again, and supply their own plans.
- An agent can answer the editor's narrow questions instead of the local model:
  whether a clip ends before its speaker has finished, whether leaving a
  passage out leaves something dangling, and which of two versions is the
  better short. List them with `clipmill_judge_questions` or
  `clipmill questions`, and send the answers with a reprompt. An agent is
  tested on the same known cases as the local model before any answer is used.
  [MCP client guide](../agents.md)
- Clips an agent or a script makes start with the caption look and brand kit
  you chose in the Studio.

## Measured on one recording

A 113-minute English discussion between many speakers, analyzed on an Apple
silicon Mac with the default local models:

- **Edges.** Of the 30 candidate clips the editor considered, 11 ended and 17
  opened while the same speaker ran straight on from one sentence into the
  next. With 0.6.0, none do. Clips stayed about as long, 35 seconds on average.
- **Endings.** The editorial model passed the ending check and ruled on the
  candidate endings where the speaker went on.
- **Removals and edits.** The editorial model passed the removal check and
  refused all four passages the planner proposed to leave out, hearing a line
  that stayed depend on each. When a connected agent allowed two
  removals instead, the model passed the comparison check and preferred the
  whole moment to both shorter clips, so they were suggested whole. All ten
  suggested clips play one stretch of the recording each.
- **A smaller model.** On a 12-minute excerpt of the same discussion, the
  4-billion-parameter model passed the ending and removal checks and
  suggested three clips; the analysis took 15 minutes. One of its clips opened
  on a reply and finished on a greeting, which 0.6.0 now refuses.
- **Time.** Analysis took about an hour. Reading the recording into memory took
  21 minutes, marking up its lines 15, framing 12 and recognising speech 7. The
  decisions after that took 17 minutes.
